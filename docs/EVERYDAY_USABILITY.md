# 일상 사용성 기능

이번 변경은 기존 Flutter 프로젝트와 기기 내 SQLite를 사용합니다. 별도 서버나 회원가입은 없습니다.

## 사용 흐름

- **목록 → 먹음·폐기**: 상세 화면을 거치지 않고 처리량을 선택합니다. 저장 후 8초 동안 표시되는 `실행 취소`로 해당 재료의 가장 최근 처리를 되돌립니다. 수량과 처리 금액이 함께 복원되며 되돌린 기록은 주간 집계에서 빠집니다.
- **한 번에 등록**: 이전 등록 이력·기본 목록에서 여러 재료를 선택하거나 직접 추가합니다. 각 재료의 소비기한을 새로 고르고 실제 구매금액은 선택 입력합니다. 모든 항목을 하나의 트랜잭션으로 저장합니다.
- **상단 장바구니 → 장보기**: 구매할 재료·수량을 저장합니다. 같은 이름·단위 종류·수량은 중복으로 담지 않습니다. 선택한 재료의 구매 등록을 완료하면 재고에 추가하면서 장보기 목록에서 제거합니다. 취소하거나 저장에 실패하면 장보기 항목은 유지됩니다.
- **설정 → 소비기한 알림**: 기본은 꺼짐입니다. 원하는 시각에 소비기한 3일 전·1일 전·당일인 재고를 하루 한 번 묶어 알려줍니다. Android 절전 정책에 따라 지정 시각보다 늦게 전달될 수 있습니다. 알림을 누르거나 앱을 직접 열면 해당 재료의 소비량 확인 팝업을 엽니다. 여러 재료는 소비기한순으로 하나씩 표시합니다.
- **폐기 → 사유 선택 / 이번 주 폐기 내역**: 사유는 선택 입력입니다. 주간 화면에서 사유와 재료별 기록을 확인합니다. 금액 미입력과 0원을 구분하며, 입력하지 않은 사유를 추정하지 않습니다. 구매 힌트는 해당 주 기록에 기반한 참고 안내입니다.

## 저장 규칙

SQLite 버전 1 또는 2에서 3으로 기존 데이터를 유지하며 이전합니다. 기존 `foods`, `records`를 삭제하지 않습니다. 폐기 사유, 실행 취소 표시와 장보기 저장을 추가합니다.

실행 취소는 해당 재료의 가장 최근 유효 처리에만 적용합니다. 되돌린 요청 ID도 보존하므로 오래된 저장 요청이 다시 들어와도 재고를 중복 차감하지 않습니다. 처리 이력이 있는 재료의 구매금액·원래 수량 변경 및 삭제 제한은 실행 취소 이후에도 유지됩니다.

장보기는 구매 예정 목록입니다. 실제 소비기한·구매금액을 미리 추정하지 않으며 구매 등록 시 다시 입력합니다. 구매 등록은 재고 저장과 장보기 제거를 함께 처리합니다.

## 구현 위치

- `lib/main.dart`: 빠른 처리, 실행 취소, 알림 진입, 화면 연결
- `lib/ui/batch_registration.dart`: 일괄 등록
- `lib/ui/shopping_page.dart`: 장보기
- `lib/ui/waste_insights_view.dart`: 주간 인사이트
- `lib/domain/shopping.dart`, `lib/domain/waste_insights.dart`: 장보기 모델과 집계
- `lib/data/inventory_repository.dart`: 스키마 이전, 실행 취소, 원자적 구매 등록
- `lib/services/reminder_service.dart`, `lib/ui/reminder_settings.dart`: 알림 연결·설정
- `android/app/src/main/kotlin/com/detabev/recare/`: Android 알림 예약·수신·권한 처리

실기기의 권한 창, 절전 상태에서의 알림 전달, 재부팅 후 예약 복원은 연결된 Android 기기에서 추가 확인해야 합니다. 이 클라우드에는 현재 연결 기기가 없습니다.


## 소비기한 확인 팝업 (1.1.0+5)

절반·1/3·2/3·모두·아직 안 먹음 중 선택한 뒤 저장합니다. 기준은 현재 남은 재고이며 이미 기록한 소비량을 중복으로 답하지 않도록 안내합니다. `건너뛰기`는 현재 재료만, `오늘 모두 건너뛰기`는 남은 대상 모두를 오늘 확인에서 제외합니다. 두 경우 재고는 바뀌지 않습니다. 답변은 재실행 후에도 유지되며 다음 확인 날짜에는 다시 묻습니다. 전체 변경 요약은 [변경 내역](../CHANGELOG.md)을 참고하세요.
